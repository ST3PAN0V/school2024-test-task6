# Отчёт об отклонениях рабочего времени

Консольное решение на C++17 для **отборочного задания Летней ИТ-школы КРОК 2024 года**. Программа читает записи рабочего времени за неделю и находит сотрудников, у которых суммарное время отличается от нормы более чем на 10%.

**Автор решения:** Степанов Артём Алексеевич, [ST3PAN0V](https://github.com/ST3PAN0V).

## Задача и формат данных

Система учёта времени выгружает недельный `report.txt`. В первой строке указана норма часов на сотрудника. Каждая следующая строка содержит одну запись формата TSR-3: UUID сотрудника, фамилию, имя, отчество, дату и часы.

```text
<employee UUID> <last name> <first name> <patronymic> <dd.MM.YYYY> <hours>
```

Одному сотруднику может соответствовать несколько записей. Программа суммирует часы и записывает в `result.txt` сотрудников, вышедших за допустимый диапазон: фамилию с инициалами и отклонение от нормы со знаком.

```text
<last name> <first initial>.<patronymic initial>. <signed difference from target>
```

Сначала выводятся сотрудники с недоработкой, затем — с переработкой. Внутри каждой группы записи отсортированы лексикографически по имени. Отклонение ровно на 10% считается допустимым.

Например, при норме 40 часов в отчёт попадут суммы меньше 36 или больше 44 часов. Само отклонение рассчитывается от 40 часов, а не от границы допустимого диапазона.

## Реализация

- C++17 и стандартная библиотека; сборка через CMake.
- Ввод и вывод через файлы, без интерактивных запросов.
- Агрегация с помощью `std::map<Employee, float>`.
- Два прохода по упорядоченным результатам: сначала отрицательные отклонения, затем положительные.
- Обработка имён в UTF-8 для получения кириллических инициалов.

## Сборка

Требуются компилятор C++17, CMake 3.11 или новее и установленная системная локаль **`ru_RU.UTF-8`**. Программа создаёт её явно; одного изменения переменной окружения в оболочке недостаточно для установки локали.

В репозитории есть старые каталоги сборки. Создайте новый, чтобы CMake настроил пути для вашего компьютера:

```bash
git clone https://github.com/ST3PAN0V/school2024-test-task6.git
cd school2024-test-task6
mkdir -p build-local
cd build-local
cmake .. -DCMAKE_BUILD_TYPE=Release
cmake --build .
```

## Запуск

Выполните команды из созданного каталога сборки:

```bash
./Imbalance_monitoring
cat ../result.txt
```

Программа читает `../report.txt` и записывает `../result.txt` относительно **рабочего каталога процесса**. Пути файлов не передаются через аргументы командной строки. При запуске выходной файл перезаписывается.

Для обработки другого отчёта поместите его в `report.txt` в корне репозитория, соблюдая описанный формат.

## Проверка результата

Автоматического набора тестов в проекте нет. Используйте приложенный отчёт как пример, проверяйте содержимое выходного файла и сообщения в stderr. Точка входа перехватывает исключения и всё равно возвращает `0`, поэтому одного кода завершения процесса недостаточно для проверки успешного выполнения.

Полезные граничные случаи: сумма точно равна норме, отклонение ровно на 10% в каждую сторону и значения сразу за границами допустимого диапазона.

## Ограничения

Решение рассчитано на отчёт, который уже содержит одну рабочую неделю. Даты считываются, но не используются для фильтрации.

Текущее сравнение ключей в `map` использует полное имя сотрудника, а не UUID. Поэтому записи разных сотрудников с одинаковыми ФИО будут объединены. Пути файлов и допустимое отклонение заданы в `src/tools.h`; разбор предполагает корректный формат входных данных.
